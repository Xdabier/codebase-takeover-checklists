# Codebase takeover checklists

Three checklists for the moment a software product changes hands: you take over an existing codebase, your only developer leaves, or you are about to hire a remote developer you have never met.

They are written for founders, in plain words. Each one is a short list you can tick off, with a link to the full guide and its sources.

- **[The first 14 days of a codebase takeover](first-14-days-of-a-takeover.md)**: what to check in the first five days, and what to fix in the days after.
- **[Your developer left: the first 48 hours](developer-left-first-48-hours.md)**: the accounts to secure first, and the order that avoids locking yourself out.
- **[Ten checks before you hire a remote developer](ten-checks-before-hiring-a-remote-developer.md)**: how to tell that a remote developer is real, can do the work, and leaves you in control.

## How to use them

- Copy a file into your own repository or an issue, and tick the boxes as you go.
- Each checklist also exists as one printable image on its guide page.
- Nothing here needs you to read code.
